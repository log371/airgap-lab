01 / INTENTION

Un outil réduit.
Un périmètre explicable.

Avant de déployer une IA sur une machine réemployée ou dans un environnement sur site, il faut comprendre le socle disponible. Airgap Lab commence par cette observation simple.

Le projet relie développement Python, inspection systèmes et IA locale. Son intérêt tient à la maîtrise des entrées, à la lisibilité des sorties et à la documentation des limites.

B / SUR TA MACHINE

L’inspecteur Python

Le serveur FastAPI s’exécute localement. Il expose l’inventaire et interroge une adresse Ollama fixe sur loopback.

  • psutil + platform → inventaire matériel
  • 127.0.0.1:11434/api/tags → métadonnées
  • /api/snapshot → rapport JSON
Navigateur → 127.0.0.1 → FastAPI
Frontière de sécurité

La commande documentée lie le serveur à 127.0.0.1. L’API expose des métadonnées sans authentification : elle doit rester locale. Le nom Airgap Lab ne constitue pas une certification d’isolement.

05 / MÉTHODE

De l’idée à la trace.

Un parcours de travail explicite pour préparer une livraison qui reste vérifiable.

  1. Arbitrer

    Choisir un livrable et consigner sa raison.

  2. Réduire

    Définir le minimum testable et le hors périmètre.

  3. Essayer

    Documenter l’environnement, le protocole et le résultat observé.

  4. Livrer

    Relier chaque critère à une trace et relire les limites.

06 / REPRODUIRE

Le code reste utilisable localement.

Récupère le dépôt, prépare un environnement Python puis lance l’inspecteur. Le serveur n’est pas nécessaire pour consulter ce dossier ou utiliser l’atelier.

Installation complète dans le README ↗
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
python -m uvicorn airgap_lab.app:app \
  --host 127.0.0.1 --port 8765

Depuis la racine du dépôt · puis ouvrir http://127.0.0.1:8765
