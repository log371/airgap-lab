# Audit et nettoyage — 17 novembre 2026

## Périmètre et méthode

Audit de sécurité du dossier public, de l’atelier, de ses assets, de la configuration Vercel et de la fiche ajoutée au portfolio : huit fichiers dans l’instantané initial. Revue indépendante de l’architecture et du code, puis validation par lecture des flux et reproduction isolée du HTML généré. Aucun exploit n’a été exécuté contre les visiteurs.

L’inspecteur Python a fait l’objet d’une revue complémentaire de ses entrées/sorties et de tests de durcissement. Ce travail ne constitue pas un audit intégral de `sentinel-v3`, de ses autres routes, de ses dépendances ou des droits des comptes GitHub/Vercel.

## Défaut confirmé et corrigé

**Injection DOM persistante par import JSON — CWE-79, gravité faible.** Les identifiants des tâches, essais, hypothèses et critères pouvaient être insérés sans échappement dans des attributs HTML. L’attaquant devait fournir une sauvegarde piégée et convaincre l’utilisateur de l’importer puis d’ouvrir une vue concernée. L’impact établi concerne l’exécution dans l’origine de l’atelier et l’intégrité de ses données locales, sans preuve de compromission serveur ou de compte.

Correction publiée dans le commit [`670e52e`](https://github.com/log371/airgap-lab/commit/670e52e2ce4313278326684db27dcf21e24055fd) :

- Validation commune aux imports et à la restauration du stockage : types, identifiants uniques, statuts, options, dates et traces requises.
- Échappement des identifiants dans tous les attributs concernés.
- Fichiers limités à 2 MiB et collections bornées.
- Sauvegarde corrompue conservée sans écrasement automatique ; travail neuf exportable et réactivation après import valide.
- Script autonome autorisé par empreinte SHA-256 dans la page et la configuration Vercel. Les gestionnaires d’événements injectés ne sont plus autorisés.

## Durcissement complémentaire

- Requêtes Ollama sans proxy d’environnement et sans redirection HTTP, conservant l’adresse fixe loopback et les bornes de réponse/délai.
- Validation des en-têtes Host sur l’API locale et réponses `Cache-Control: no-store`.
- Suppression des imports Python inutilisés.
- Documentation de sécurité et procédure de renouvellement de l’empreinte CSP.
- Références au nombre historique de tests remplacées par les traces GitHub Actions.
- Retour au dossier accessible sur mobile et barre latérale défilante sur les petits écrans de bureau.

## Vérifications

[Exécution GitHub Actions du correctif](https://github.com/log371/airgap-lab/actions/runs/44189946672) : **14 tests Python et 5 tests JavaScript réussis**. Une dépréciation de la bibliothèque TestClient/httpx est signalée par les dépendances, sans échec de test. Les réponses Ollama sont simulées ; aucun résultat d’inférence réelle n’en découle. L’environnement local ne pouvait pas installer les dépendances Python faute de résolution de PyPI ; les tests Python ont donc été exécutés sur GitHub Actions.

Les régressions couvrent les identifiants malveillants des quatre collections, les enregistrements invalides, les preuves manquantes, le stockage corrompu, le changement d’option, les huit vues, le passage export/import et la concordance du script avec son empreinte CSP. Les tests Python couvrent aussi les réponses invalides ou trop volumineuses, le timeout, les limites des modèles, les redirections, les proxys et les Host interdits.

La production Vercel du correctif a atteint l’état READY. Le navigateur a chargé l’atelier, affiché la comparaison, confirmé la présence de la politique par empreinte et n’a remonté aucune erreur JavaScript lors de cette vérification.

## Limites

Aucun audit exhaustif des dépendances, test d’intrusion réseau, contrôle de tous les en-têtes réellement servis ou mesure de performance n’a été réalisé. Les tests de l’atelier exécutent son code avec un DOM simulé ; le contrôle navigateur de production est un contrôle complémentaire, pas une suite E2E complète. La v0.2 fonctionnelle reste à arbitrer. Le projet ne certifie pas l’air-gap.

Le rapport du scan initial est conservé séparément de cette note de remédiation. Aucun comptage fiable de consommation de tokens n’était disponible pour ce scan.
